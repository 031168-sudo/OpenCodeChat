# OpenCodeChat — handoff для работы на GitHub

> Документ для агентов, которые работают только с репозиторием и GitHub
> Actions и не имеют доступа к локальной машине разработчика или приватным
> серверам. В файле намеренно нет абсолютных локальных путей, имён хостов,
> приватных адресов, идентификаторов сессий и секретов. Для примеров используйте
> placeholder-адреса вида `https://your-opencode-host.example`.

## 1. Кратко о проекте

**OpenCodeChat** — нативный Android-клиент для сервера **OpenCode 2**.

- Язык: Kotlin.
- UI: Jetpack Compose, Material 3.
- Пакет: `ru.alfanomy.opencodechat`.
- `minSdk` 26, `targetSdk` 35, `compileSdk` 35.
- Версия: `versionCode 1`, `versionName 1.0`.
- Сеть: `HttpURLConnection` + `org.json`, без сторонних HTTP-библиотек.
- Авторизация: HTTP Basic; логин и пароль задаёт пользователь.
- Сервер: OpenCode 2, API v2 (`/api/...`).
- Репозиторий: https://github.com/031168-sudo/OpenCodeChat

Приложение не должно быть привязано к конкретному серверу, хосту, домену
или сети. Адрес сервера вводится пользователем при первом запуске.

## 2. Карта репозитория

Основной код:

- `app/src/main/java/ru/alfanomy/opencodechat/MainActivity.kt`
  — экраны, навигация, чат, настройки, профили, диалоги.
- `app/src/main/java/ru/alfanomy/opencodechat/ApiClient.kt`
  — HTTP-клиент, парсинг API, сообщения, модели, речь.
- `app/src/main/java/ru/alfanomy/opencodechat/Prefs.kt`
  — настройки в SharedPreferences.
- `app/src/main/java/ru/alfanomy/opencodechat/ChatCache.kt`
  — локальный кэш последней истории.

Сборка и документация:

- `.github/workflows/android.yml` — сборка debug-APK в GitHub Actions.
- `README.md` — краткое описание и инструкция по сборке.
- `AGENTS.md` — подробности по API, архитектуре и поведению приложения.

Результат сборки:

- `app/build/outputs/apk/debug/app-debug.apk`.

Все пути в этом документе — относительно корня репозитория.

## 3. Как работать с проектом на GitHub

1. Прочитайте `README.md`, `AGENTS.md` и этот файл.
2. Работайте только в репозитории; не предполагайте доступ к живому серверу.
3. Перед изменениями проверьте `git status` и изучите затрагиваемые файлы.
4. Не добавляйте в исходники конкретные адреса серверов, домены, IP или
   учётные данные.
5. Основная проверка изменений — сборка debug-APK в GitHub Actions.
6. Не коммитьте, не пушьте, не публикуйте APK и не создавайте релизы без
   явной команды пользователя.
7. Если изменение меняет поведение, обновите `README.md` или `AGENTS.md`.
8. Секреты, ключи, `.env`, keystore и дампы сессий не должны попадать в git.

## 4. Сборка и CI

### GitHub Actions

Workflow: `.github/workflows/android.yml`.

- Запускается при push в `main`, в pull request и вручную
  (`workflow_dispatch`).
- JDK 17 (Temurin).
- Android SDK: `compileSdk 35`, build-tools 35.0.0.
- Кэшируется debug keystore.
- Собирает `:app:assembleDebug`.
- Загружает артефакт `OpenCodeChat-debug-apk`.
- Хранение артефакта: 14 дней.

Важно:

- Используется `android-actions/setup-android@v4`.
- Не откатывайтесь на `@v3`: на GitHub runners с Node.js 24 он падает.
- Debug-APK из CI может быть подписан другим отладочным ключом, чем
  предыдущая сборка. Если обновление не ставится поверх, нужно удалить
  старую версию.
- Для стабильных обновлений нужен постоянный keystore и release-подпись.

### Локальная сборка

Gradle wrapper уже есть в репозитории. Убедитесь, что переменная
`ANDROID_HOME` указывает на Android SDK, и выполните:

```bash
./gradlew :app:assembleDebug
```

При необходимости добавьте `--offline`, если зависимости уже в кэше.

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

## 5. Требования к серверу OpenCode

Приложение рассчитано на **OpenCode 2** и API v2.

- Установщик OpenCode 2: `https://opencode.ai/v2/install`.
- Установщик `https://opencode.ai/install` ставит OpenCode 1 и **не
  подходит**.
- API должно быть доступно от корня сервера: `https://host/api/...`.
- `GET /api/info` должен возвращать JSON с версией, а не HTML.
- HTTP Basic авторизация опциональна; если сервер без неё, пароль можно
  оставить пустым.
- Если используется HTTPS-сертификат, он должен соответствовать имени
  хоста. Нельзя открывать `https://<IP>` с сертификатом, выписанным на
  DNS-имя.
- Reverse proxy, Tailscale, VPN, Caddy и другие способы доступа — внешние
  детали. Приложение не должно на них рассчитывать.

Необязательные серверные функции:

- `/profiles/api` — синхронизация имён и папок профилей с веб-интерфейсом.
- `/speech/inference` — распознавание речи через Whisper.

Без них приложение работает: профили хранятся локально, а голосовой ввод
просто недоступен.

## 6. Основные эндпоинты API

Приложение использует API v2:

- `GET /api/info` — проверка связи и версия.
- `GET /api/project` — проекты.
- `GET /api/session` — список сессий.
- `POST /api/session` — создание сессии.
- `GET /api/session/{id}/message` — история сообщений.
- `POST /api/session/{id}/prompt` — отправка запроса.
- `POST /api/session/{id}/prompt_async` — асинхронная отправка.
- `POST /api/session/{id}/model` — модель сессии.
- `POST /api/session/{id}/agent` — агент сессии.
- `GET /api/event` — SSE-события.
- `GET /api/model`, `GET /api/provider` — модели и провайдеры.
- `GET /api/agent`, `GET /api/command` — агенты и команды.
- `GET /api/session/{id}/form` и
  `POST /api/session/{id}/form/{formID}/reply` — формы и вопросы.
- `GET /api/session/{id}/permission` и
  `POST /api/session/{id}/permission/{id}/reply` — разрешения.
- `POST /api/pty` — shell-команды для операций с проектами.
- `POST /profiles/api` — опциональная синхронизация профилей.
- `POST /speech/inference` — опциональное распознавание речи.

При работе с историей не рассчитывайте на неограниченный размер страницы.
Сервер может ограничивать `limit`; используйте пагинацию и курсоры.

## 7. Поведение приложения

### Первый запуск и подключение

- Если адрес сервера не задан, открываются настройки.
- Пользователь может указать публичный адрес и/или адрес по Tailscale.
- Достаточно одного доступного адреса.
- Логин и пароль — HTTP Basic; пароль может быть пустым.
- `Prefs.defaultRoot` задаёт корень для новых проектов, если у профиля нет
  своей папки.
- Если сохранённой модели нет на сервере, приложение выбирает доступную,
  предпочитая провайдера `opencode`.

### Профили

- Профиль — это удобное рабочее пространство, а не средство безопасности.
- Профиль содержит имя, корневую папку, модель, агента, вариант, скрытые
  модели, последнюю сессию и каталог.
- Список профилей может синхронизироваться через `/profiles/api`.
- Если API недоступен, профили сохраняются локально с id `local-…` и позже
  могут быть перенесены на сервер.
- Логин и пароль общие; профили не изолируют доступ.

### Чат и сообщения

- Ответы приходят потоком через SSE.
- Сообщения рендерятся блоками: текст, reasoning, вызовы инструментов,
  ошибки провайдера.
- Вложения-изображения и файлы отправляются как data-URI.
- Под сообщениями есть время, копирование, откат до вопроса и длительность
  хода.
- История подгружается страницами; старые вложения и тяжёлые tool-выводы
  не запрашиваются без необходимости.
- Пока ассистент работает, показываются индикаторы и «opencode работает…».
- При возврате в приложение состояние сессии перепроверяется.

### Дополнительные возможности

- Выбор модели, агента и уровня размышлений.
- Слэш-команды: `/new`, `/undo`, `/compact`, `/fork`, `/export`, `/share`
  и пользовательские команды сервера.
- Разрешения и формы (вопросы) OpenCode.
- Файлы проекта: просмотр, поиск, загрузка, создание папок, переименование
  и удаление.
- `@` — выбор файла проекта в контекст запроса.
- Использование токенов и стоимости по сессии, проекту и профилю.
- Оформление: тема, шрифт, размер шрифта.
- Голосовой ввод через Whisper, если он настроен.
- Кэш последней сессии для быстрого открытия.

## 8. Известные подводные камни

### HTML вместо JSON

Симптом:

```text
Value <!doctype of type java.lang.String cannot be converted to JSONObject
```

Причина: приложение запросило `/api/info`, а сервер вернул HTML-страницу.

Что проверять:

- адрес должен быть корнем сервера, без `/api`, `/apk` и лишних путей;
- сервер должен быть OpenCode 2, а не OpenCode 1;
- reverse proxy должен проксировать на API OpenCode, а не на статический
  сайт;
- `GET /api/info` должен возвращать JSON.

### Сертификат и IP

Если HTTPS-сертификат выписан на DNS-имя, открытие по IP даст ошибку
сертификата. Используйте имя, для которого выпущен сертификат.

### Авторизация

`401 Unauthorized` означает неверный логин или пароль. Пользователь должен
проверить настройки; не встраивайте учётные данные в код.

### Сборка

- `setup-android@v3` несовместим с текущими GitHub runners.
- Debug-подпись из CI может отличаться от предыдущей.
- Для release-сборки нужен постоянный keystore, которого в репозитории нет.

## 9. Текущее состояние

- Проект собирается в GitHub Actions и выдаёт debug-APK.
- Поддерживается OpenCode 2 API.
- Веб-прокси и Whisper не обязательны.
- Профили работают локально без `/profiles/api`.
- Нет известных блокеров.
- CI является основной проверкой сборки; отдельного набора тестов в
  документации не заявлено.

Не предполагайте, что из GitHub доступен живой сервер, база данных,
локальный кэш или приватная сеть. Вся работа должна опираться на код,
документацию и артефакты CI.

## 10. Возможные улучшения

Обязательных правок нет. Идеи на будущее:

1. Показывать понятную ошибку, если `/api/info` вернул HTML вместо JSON.
2. В проверке соединения требовать JSON с версией, а не просто HTTP 200.
3. Нормализовать введённый адрес: убирать лишние `/api`, `/apk` и
   завершающий `/`.
4. Добавить постоянный release-keystore и release-сборку.
5. Добавить тесты для парсинга API и ключевых состояний UI.
6. Увеличивать `versionCode`/`versionName` при выпусках.
