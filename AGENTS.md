# AGENTS.md — проект OpenCodeChat

## Что это

Нативное Android-приложение (Kotlin + Jetpack Compose) — клиент для **сервера
opencode**. Позволяет работать с opencode с телефона через свой удобный
интерфейс, а не через веб в браузере.

- Пакет: `ru.alfanomy.opencodechat`
- Исходники: `/home/andrey/OpenCodeChat`
- Код: `app/src/main/java/ru/alfanomy/opencodechat/`
  - `MainActivity.kt` — UI (экраны SETTINGS / SESSIONS / CHAT)
  - `ApiClient.kt` — HTTP-клиент к API opencode
  - `Prefs.kt` — настройки (адрес, логин, пароль, модель)

## Сборка

Только в GitHub Actions, на машине разработки не собирается: она слабая
(1 CPU, 2.9 ГБ RAM), JDK, Gradle и Android SDK здесь не ставятся.

Пайплайн `.github/workflows/android.yml` (`ubuntu-latest`, JDK 17, Android SDK)
запускается на пуш в `main`, на PR и вручную (`workflow_dispatch` — кнопка
Run workflow в интерфейсе GitHub). Результат — артефакт
`OpenCodeChat-debug-apk` с `app-debug.apk` внутри.

- Debug-APK из CI подписывается постоянным debug-ключом, который workflow
  создаёт сам и кэширует (`~/.android`, ключ `android-debug-keystore-v2`);
  `app/build.gradle.kts` берёт его явно (`signingConfigs.ci`, путь можно
  переопределить переменной `DEBUG_KEYSTORE_PATH`). Поэтому обновления
  ставятся поверх. Если кэш Actions вычистится (7 дней без сборок), ключ
  сгенерируется заново и для установки придётся один раз удалить приложение;
  для полной независимости нужен постоянный keystore в Secrets.
- APK каждой успешной сборки `main` публикуется в GitHub Releases:
  **https://github.com/031168-sudo/OpenCodeChat/releases/latest/download/opencode-chat-debug.apk**

## Веб-интерфейс на старых браузерах

- Caddy для `gmpony.alfanomy.ru` проксирует на `127.0.0.1:4097` —
  это `~/caddy/oc-web-proxy.js` (Node). Прокси вставляет
  `/_assets/oc-polyfill.js` в HTML перед модулями приложения.
- Полифилл `~/caddy/oc-polyfill.js` закрывает `URL.canParse`, `URL.parse`,
  `Promise.withResolvers`, `Promise.try`, `Map.groupBy`, `Object.groupBy`,
  методы Set и др. — чтобы веб-UI работал в Chrome <= 116 (MacBook 2010).
- Прокси стартует по cron `@reboot`; каждую минуту cron проверяет, что порт
  4097 слушается, и поднимает процесс заново при падении.
- Отключить: вернуть в `~/caddy/Caddyfile` `reverse_proxy 127.0.0.1:4096`,
  перезагрузить Caddy и остановить `oc-web-proxy.js`.

### Профили: веб отключён, Android синхронизируется

- Профили в вебе **отключены** (компромисс): веб показывает все проекты,
  без чипа, пункта в настройках и фильтра. Cookie `oc_profile` для веба
  игнорируется, модель профиля не подменяет `/api/config`. Это **не защита**,
  а удобство: Basic auth у всех общий.
- `oc-web-proxy.js`:
  - отдаёт `GET/POST /profiles/api` (для Android) и `GET /profiles/models`;
  - хранит профили в `~/caddy/oc-profiles.json`;
  - фильтрация `/api/project`, `/api/session` и `/api/config` и вставка
    `oc-profiles.js` отключены флагом `WEB_PROFILES_ENABLED = false`;
  - вставляет `/_assets/oc-new-project.js` (только кнопка «＋ Новый проект»).
- Профили приложения (Android) синхронизируют с сервером **имя и папку**:
  читаются из `/profiles/api` (публичный адрес) при старте и при открытии
  настроек, добавление/изменение/удаление идут через тот же API
  (`keepModel: true` сохраняет модель, заданную в вебе). Модель, агент,
  вариант, скрытые модели, последняя сессия и каталог остаются локальными;
  первый синк добавляет старые локальные профили на сервер; при недоступности
  API используется локальный кэш, а новые профили сохраняются локально
  (id `local-…`) и позже переносятся на сервер, когда `/profiles/api`
  появится. На «чистом» opencode без прокси профили полностью локальные.
  В настройках профиля показывается сводка
  модели/агента/варианта и кнопка «Настроить» — она открывает чат, где эти
  значения меняются. Активный профиль выбирается на каждом устройстве отдельно.
- Чтобы снова включить профили в вебе: поставить `WEB_PROFILES_ENABLED = true`,
  вернуть вставку `oc-profiles.js` в HTML, поднять `PROFILES_SCRIPT_VERSION`
  и перезапустить прокси. Service worker может держать старый HTML — помогает
  жёсткая перезагрузка или очистка данных сайта.

### Все проекты и новый проект на главной

- Штатная главная веб-UI показывает в сайдбаре только недавно открытые
  проекты (их список хранится в localStorage). Прокси подменяет в
  runtime-чанке `let p=t(()=>r.list().map(f))` на объединение недавних
  и всех проектов из `/api/project`; на главной видны все проекты.
  Проверка: заголовок ответа `x-oc-runtime-patch: all-projects` у
  `/_assets/runtime-*.js`.
- Если после обновления opencode этой строки в runtime-чанке нет, патч
  молча не применится и снова будут только недавние проекты — нужно
  обновить `RUNTIME_PROJECTS_OLD`/`RUNTIME_PROJECTS_NEW` в
  `oc-web-proxy.js`.
- Под заголовком «Проекты» `oc-new-project.js` добавляет текстовую кнопку
  «＋ Новый проект», которая нажимает штатную иконку добавления (папка с
  плюсом); так кнопку видно без наведения.
- После правки `oc-new-project.js` поднять `NEW_PROJECT_SCRIPT_VERSION` в
  `oc-web-proxy.js` и перезапустить прокси; для runtime-патча достаточно
  перезапуска прокси. Service worker может держать старые ассеты — помогает
  жёсткая перезагрузка или очистка данных сайта.

## Сервер opencode

- Локально: `http://127.0.0.1:4096` (за Caddy на `https://gmpony.alfanomy.ru`).
- Версия: **2.0.32** (API v2, все маршруты под `/api/...`).
- **Авторизация: HTTP Basic**, пользователь `opencode`, пароль —
  `password` из `~/.config/opencode/service.json` (в `server.env` синхронизирован).
- Полный OpenAPI: `GET /openapi.json` (JSON), с Basic-авторизацией.

## Используемые эндпоинты API (v2)

- `GET /api/info` — проверка связи / версия
- `GET /api/project` — проекты (`canonical` = путь)
- `GET /api/session?limit=1000[&directory=...]` — сессии: `{data:[...]}`
- `POST /api/session` `{title, location:{directory}}` — создать сессию
- `GET /api/session/{id}/message?limit=1000&order=asc` — сообщения: `{data:[...]}`
  (типизированные: `user` / `assistant` с `content:[text|reasoning|tool]`)
- `POST /api/session/{id}/model` `{model:{id,providerID,variant?}}` — модель сессии
- `POST /api/session/{id}/agent` `{agent}` — агент сессии
- `POST /api/session/{id}/prompt` `{text, files:[{uri,name}]}` — отправить промпт
- `GET /api/event` (SSE) — события: `data:{type,data}`, например
  `session.text.delta`, `session.step.ended`, `session.execution.succeeded`
- `GET /api/model`, `GET /api/provider` — модели и провайдеры
- `GET /api/agent`, `GET /api/command` — агенты и команды
- `GET /api/session/{id}/form` + `POST .../form/{formID}/reply` — формы (вопросы)
- `GET /api/session/{id}/permission` + `POST .../permission/{id}/reply` — разрешения
- `POST /api/pty` — shell (создание проектов: mkdir + git init)
- `POST /speech/inference` (Caddy) — распознавание речи Whisper (large-v3 q5),
  защищено тем же Basic auth, что и сервер opencode.

### Распознавание речи

- Модель: `whisper.cpp` **large-v3 q5** — файл
  `/opt/whisper.cpp/models/ggml-large-v3-q5_0.bin`.
- В контейнере `whisper-server` основной процесс остаётся на `:8080` с моделью
  `small`; рядом запущен второй сервер large-v3 на `:18080` (GPU).
- Скрипт запуска: `/opt/whisper.cpp/models/whisper-large-start.sh`; cron каждую
  минуту проверяет и поднимает его при падении.
- Caddy `handle_path /speech/*` → `172.17.0.2:18080` с Basic auth
  (`opencode`); приложение ходит на `POST /speech/inference`.
- Второй Caddy-сайт `http://100.75.84.42:18080` (Basic auth) отдаёт тот же
  Whisper напрямую через Tailscale; приложение использует его при прямом
  подключении.
- Важно: на хосте сейчас рассогласование драйвера NVIDIA (`nvidia-smi` не
  работает, новые GPU-контейнеры не стартуют). Уже запущенный контейнер
  `whisper-server` работает; после перезагрузки/пересоздания контейнера может
  потребоваться починка драйвера хоста.

#### Распознавание речи на машине разработки (не на домашнем сервере)

Отдельная установка: здесь whisper не используется — CPU без AVX (i7 M 620),
whisper base идёт медленнее реального времени (11 с речи ≈ 64 с). Вместо него
`sherpa-onnx` в `~/vosk/`:

- `asr_server.py` — HTTP-сервер, совместимый с whisper.cpp:
  `POST /inference` (multipart, поле `file`) → `{"text": "..."}`; слушает
  `0.0.0.0:18080`; запуск `~/vosk/start.sh`, cron `@reboot` и проверка раз в
  минуту (`~/vosk/keepalive.sh`), лог `~/vosk/asr.log`.
- Русская модель — Vosk small-ru (zipformer, int8, `~/vosk/model`): ~9× быстрее
  реального времени.
- Английская речь — zipformer small en int8 (`~/vosk/en`). Включается, только
  когда русская модель выдала бессмыслицу: проверка по словарям в `~/vosk/lid.py`
  (русский — 1,45 млн словоформ хэшами в `~/vosk/wl/ru_words.npy`). Если и
  английская модель выдаёт бессмыслицу, результат отбрасывается.
- Пунктуация и регистр — RUPunct small int8 (`~/vosk/punct`, `~/vosk/punct.py`).
- Числительные (`~/vosk/numwords.py`): количественные → цифрами («двадцать
  пять» → 25, «полтора» → 1,5), порядковые остаются словами («в две тысячи
  двадцать пятом году»), запятые/тире внутри числительных убираются.
- Термины (`~/vosk/en_terms.py` + `~/vosk/en_terms.json`): русская транскрипция
  → латиница (OpenCode, Kotlin, pull request, GitHub и др., с падежными
  окончаниями). JSON правится на ходу, перезапуск не нужен.
- Длинные записи режутся по тихим местам на куски ~8 с (zipformer падает на
  кусках > 20 с); на стыке изредка может потеряться слово.
- Приложение менять не нужно: для адреса без `gmpony.alfanomy.ru` функция
  `speechUrlFor()` даёт `http://<host>:18080/inference`, то есть
  `http://opencode.tailaf52ce.ts.net:18080/inference` через Tailscale.
- Ограничения: английский текст идёт без пунктуации; незнакомые английские
  слова внутри русской фразы Vosk пишет кириллицей; «один» иногда становится
  «1»; разряды в числах без разделителей (1200, а не 1 200).
- Мультиязычная модель (8 языков, ru+en в одной) проверялась: качество хорошее,
  но 0,85× реального времени и ~480 МБ памяти — от неё отказались.

Модель по умолчанию: `opencode` / `deepseek-v4.1-flash`.

## Как устроено в приложении

- Сеть: `java.net.HttpURLConnection` + `org.json` (без сторонних зависимостей,
  чтобы собиралось офлайн). Basic auth в заголовке `Authorization`.
- Отправка: `POST /session/{id}/prompt_async` (асинхронно, сервер доделывает,
  даже если приложение закрыто) + стрим `GET /event` (SSE) в реальном времени.
  По завершении (событие `session.idle`) перечитывается `GET .../message`.
- Настройки хранятся в SharedPreferences (`Prefs`).

## Что уже работает

- Название приложения — **OpenCode**; иконка в стиле «матричного дождя»
  (adaptive icon: зелёные символы на чёрном + терминальный «>_»).

- Проверка связи, список сессий, создание чата, история, отправка, ответ.
- Стриминг ответа в реальном времени (SSE `GET /event`, события
  `message.part.delta` / `message.part.updated`).
- Список проектов (объединение `GET /project` + каталоги всех сессий
  `GET /api/session`) и создание нового проекта (mkdir + git init через PTY +
  `POST /project/git/init`). Имя берётся из поля `name` (переименование в вебе),
  аватарка — из `icon` (`url`/`override`/`color`): если картинки нет, рисуется
  цветной квадрат с инициалами. Переименование в вебе создаёт **вторую** запись
  проекта с той же папкой, поэтому дубли по `canonical` схлопываются: остаётся
  самая свежая, но имя и иконка берутся из той записи, где они заданы.
- Выбор модели и агента вручную (модели из `GET /config/providers`, агенты из
  `GET /agent`); дефолт модели — `opencode` / `deepseek-v4.1-flash`.
- Список моделей — диалог с поиском, группировкой по провайдеру и по алфавиту,
  отметкой текущей и бейджем «Бесплатно»; смена — с подтверждением.
- Ответы ассистента во всю ширину без «пузырей» (сообщения пользователя — в
  пузыре справа), как в ChatGPT/Claude.
- Индикатор заполнения контекста сессии (кольцо) и меню сессии:
  переименовать / поделиться / экспортировать / архивировать / удалить.
- На экране проекта кнопка «Использование» считает стоимость и токены по
  сессиям каталога (включая подсессии, с пагинацией списка). В диалоге есть
  период: «День», «Месяц» (текущий календарный), «Всё время» и «Период» с
  выбором дат; по умолчанию — месяц. Для дня/месяца/периода статистика
  считается по датам сообщений (`message.time.created`), поэтому текущая
  сессия, созданная раньше, учитывается за сегодня; «Всё время» — по
  агрегатам сессий.
- Файлы проекта: экран из меню «+» в чате и иконка папки на экране проекта.
  Просмотр каталогов, поиск (`/api/fs/find`), предпросмотр текста и картинок
  (`/api/fs/read/*`), загрузка (`/api/experimental/fs/write`), создание папки,
  переименование и удаление файлов/папок (через PTY: `mkdir`, `mv`, `rm -rf`).
  У файла в меню «⋮» и в окне просмотра есть «Скачать на телефон» (в «Загрузки»
  через MediaStore, без разрешений; на Android 8–9 — системный выбор места) и
  «Редактировать» — полноэкранный редактор с моноширинным шрифтом, сохранение
  через `/api/experimental/fs/write`; файлы больше 1 МБ и бинарные не открываются.
- В поле ввода `@` открывает поиск файлов проекта с навигацией по папкам;
  выбранный файл добавляется в prompt как mention (`file://...` + `mention`),
  сервер сам читает его содержимое.
- Голосовой ввод: красная кнопка 🎤 справа от текста в композере. Запись WAV
  16 кГц mono (до 120 с), красная кнопка остановки и таймер; адрес распознавания
  выбирает `speechUrlFor()` (`/speech/inference` для домашнего сервера,
  `http://host:18080/inference` для остальных), результат вставляется в поле
  ввода. На домашнем сервере — Whisper large-v3 q5, на машине разработки —
  Vosk small-ru с пунктуацией, числами цифрами и английскими терминами.
- Слэш-команды: ввод `/` открывает меню команд (`/new`, `/undo`, `/compact`,
  `/fork`, `/export`, `/share` + пользовательские из `GET /command`).
- Композер в стиле веб-интерфейса opencode: `+` | пилюля модели ⌄ |
  круглая кнопка отправки ↑; микрофон — красный, внутри поля ввода справа от
  текста. Название модели в пилюле автоматически ужимается по ширине, чтобы
  влезало целиком.
- Диалог подтверждения разрешений (события `permission.asked` / `permission.v2.asked`,
  ответ `POST /session/{id}/permissions/{permissionID}`).
- Диалог вопросов opencode (события `question.asked` / `question.v2.asked`, ответ
  `POST /question/{requestID}/reply`), чтобы чат не «зависал» в ожидании выбора.
  Ожидающие вопросы/разрешения также подхватываются при открытии сессии
  (`GET /question`, `GET /permission`) — если их задали, пока приложение было закрыто.
- Выбор «уровня размышлений» модели (variant: Default/low/high/max) из шапки чата,
  передаётся в `prompt_async` как `variant`.
- При запуске приложение открывает последнюю сессию, в которой работал.
- В настройках есть выход «← Назад», если связь уже настроена.
- Настройки → «Оформление»: тема (авто/светлая/тёмная), шрифт
  (системный/Sans/Lora/Roboto Mono; Lora и Roboto Mono встроены в APK) и размер
  шрифта (80–140%). Есть строка-пример. Хранится в `Prefs.themeMode`,
  `Prefs.fontFamily`, `Prefs.fontScale`; применяется сразу.
- Настройки → «Подключение»: режим Авто/Публичный/Tailscale, публичный адрес,
  адрес по Tailscale (по умолчанию пустые — при первом запуске открываются
  настройки), необязательные адрес распознавания речи и корень проектов
  (`Prefs.defaultRoot`, отсюда создаются новые проекты, если у профиля нет
  своей папки), строка «Сейчас: …». В режиме Авто при старте и
  возврате из фона приложение сначала проверяет Tailscale, затем кэш/публичный
  адрес и выбирает доступный; речь при пустом адресе определяется как
  `/speech/inference` или `http://host:18080/inference`.
- Если сохранённой модели нет на подключённом сервере, приложение
  автоматически выбирает доступную (предпочитая провайдера `opencode`).
- В шапке чата слева от «Default» показывается бейдж активного канала:
  «Tailscale» или «Интернет», а рядом — имя активного профиля.
- Профили (рабочие пространства) в приложении: имя + корневая папка, свои
  модель/агент/вариант, скрытые модели, последняя сессия и каталог. Список
  профилей (имя/папка) общий с веб-интерфейсом через `/profiles/api`:
  добавление, изменение и удаление синхронизируются; модель/агент/вариант,
  скрытые модели, последняя сессия и каталог остаются локальными. В настройках
  профиля видна сводка модели/агента/варианта и кнопка «Настроить», которая
  открывает чат (там они и меняются). Логин и пароль общие (Basic auth не
  меняется), профиль — это разделение удобства, а не защита.
  Переключатель есть в списке проектов и в настройках; по умолчанию видны
  только проекты под корнем профиля. Стрелка вверх и пункт «Все проекты»
  показывают чужие/общие проекты (оба админа), новый проект создаётся внутри
  корня профиля. «Использование профиля» считает токены и стоимость по
  сессиям под корнем (рекурсивно) с тем же выбором периода: день, текущий
  месяц, всё время или произвольные даты.
- Отправка файлов/изображений (FilePartInput с data-URI) и их отображение
  миниатюрами прямо в чате. В меню «+»: «Камера» (системная камера через
  FileProvider), «Галерея» (системный выбор изображений PickVisualMedia),
  «Прикрепить файл» и «Файлы проекта».
- Сообщения рендерятся блоками: текст, «Размышление» (reasoning, только во время
  ответа) и вызовы инструментов («Редактировать … +N −M», «Оболочка …») как в
  веб-интерфейсе; в готовой истории размышления не сохраняются — только ответ.
- Под сообщениями — футер как в вебе: у вопроса время (ЧЧ:ММ), кнопки
  «откатить до этого вопроса» (с подтверждением; после отката вопрос удаляется
  с сервера, а его текст и вложения возвращаются в поле ввода — как в вебе) и
  «копировать»; у последнего
  ответа хода — время всего хода («1 мин 36 с») и копирование.
- Ошибки провайдера (`finish: "error"` + `error.message` в сообщении ассистента,
  события `session.step.failed` / `session.execution.failed`) показываются красным
  блоком с иконкой — как в вебе (например, «Insufficient account funds»).
- Для скорости и памяти сначала грузятся последние 20 вопросов и ~20 ответов
  сессии (длинные вложения и старые tool-выводы не тянутся). Вопросы и уже
  подгруженную историю не теряем: ответы сервера объединяются с текущим
  списком по id. При прокрутке вверх история автоматически подгружается
  страницами по 40 сообщений (`cursor.next`), позиция списка сохраняется по
  якорю; вверху показывается индикатор загрузки. Если пользователь читает
  историю не внизу, новые токены и сообщения не утаскивают список вниз.
  Кэш не хранит вложения и ограничен 1.5 МБ.
- Пока ассистент работает, внизу чата бегут пульсирующие точки и индикатор
  прогресса, а над композером — полоса «opencode работает…».
- Стартовые запросы (проекты, модели, агенты, команды, история) выполняются
  параллельно, чтобы чат открывался сразу.
- Управление списком моделей: «Настроить модели» в диалоге выбора модели
  (поиск по названию/ID/провайдеру, чекбоксы по провайдерам, «Показать все» /
  «Скрыть все»), выбор сохраняется.
- При переключении сессии чат сразу очищается — пока грузится новая история,
  показывается пустой чат со спиннером, а не содержимое предыдущей сессии.
- Последний экран и содержимое чата переживают перезапуск процесса: экран
  сохраняется в `Prefs.lastScreen`, история — в локальный кэш `last_chat.json`,
  поэтому при возврате в приложение показывается то же, без очистки и «прыжка».
- Если сессия ещё выполняется на сервере (`GET /api/session/active`), приложение
  показывает «opencode думает…» и по завершении само подтягивает готовый ответ.
- При возврате в приложение (`onResume`) сессия перепроверяется: если она ещё
  думает — снова включается индикатор и ожидание результата; если уже
  закончила (или SSE-соединение оборвалось) — история тихо обновляется.
- При открытии сессия сразу прокручивается в конец (без animate-«простыни»);
  при завершении ответа (`busy` true → false) фокус тоже смещается в конец.
- Если промотать историю вверх, над полем ввода появляется полупрозрачная
  круглая кнопка со стрелкой вниз — плавно прокручивает диалог в самый конец.
- Иконки Material 3 (`material-icons-extended`); тёмная тема (по системной
  настройке) + markdown в сообщениях: кликабельные ссылки, жирный, код в
  обратных кавычках (1–3 подряд), таблицы. Таблица рисуется сеткой с шапкой и
  горизонтальной прокруткой. Блоком кода считается только строка, целиком
  состоящая из ``` (возможно, с языком) — «```слово```» внутри строки остаётся
  inline-кодом.
- Текст сообщений выделяется долгим нажатием (`SelectionContainer`): ползунки
  и системное меню Android (копировать / выделить всё).
